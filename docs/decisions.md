| D-023 | 2026-10-16 | Milestone 3 chat stack. **Auth:** anonymous device sessions issued by the server (`POST /session` creates a `users` row and returns an HS256 token signed with `SESSION_SECRET`; the app stores it in AsyncStorage and sends `Authorization: Bearer`); Supabase Auth is not used. **DB:** Postgres via Drizzle ORM: node-postgres when `DATABASE_URL` is set (hosted Supabase, session pooler), otherwise PGlite persisted to `local-data/pglite`; tests use in-memory PGlite. SQL migrations generated by drizzle-kit, applied by `pnpm db:migrate` (auto-applied on startup for PGlite). Tables `users`, `conversations`, `messages`, `memories`; RLS enabled with no policies (the server connects as owner and filters by `userId`; Supabase's public API sees nothing). **API:** `GET /conversations`, `GET /conversations/:companionId/messages`, `POST /conversations/:companionId/messages` streaming SSE (`ack`, `typing`, `delta`, `bubble`, `done`, `error`), idempotent on `clientId`, one retry before the first token, no fallback provider yet. **Limits:** in-memory per-user rate limit (`RATE_LIMIT_PER_MIN`, default 20), 2,000-character messages, `KILL_SWITCH`. | Accepted | Fewest moving parts for a short demo build: no Docker, no separate auth service, zero-setup local development, and the same SQL on hosted Supabase. Refines D-003 and D-019. |

| D-038 | 2026-10-20 | Companions should feel like a real person to text. Revises D-007/D-015 guardrails: in conversation they may discuss real people, companies, products, and news with opinions, never inventing facts or quotes (look it up or say unsure), with no defamation, nothing sexual about real people, and no personal information about private individuals; they still never speak as or claim to be the person who inspired them. They stay in character and never volunteer being AI, but a sincere question about whether the user is talking to a person or an AI gets a truthful in-voice answer (not configurable). Limited web access: Anthropic server-side web search (2 per reply) and link reading (2 per reply, only links already in the conversation; blocked adult and harassment sites), plus `share_image`, which shows the preview image (`og:image`) of a page found through search with a link to the page. The server fetches that page itself, HTTPS only, public addresses only (checked on every redirect), with timeouts and size caps. Lookups are capped at 20 per user per UTC day (100 with demo Plus); `WEB_ACCESS=false` turns them off. | Accepted | Developer direction 2026-10-20: the original guardrails over-restricted the product ("Real people aren't my department"). The developer asked to stay in character even when sincerely asked; that one carve-out stays, because telling a user who genuinely asks that they are talking to a human is deceptive. No paid image-search API (developer choice); page preview images replace it. Security fixes 2026-10-20: `share_image` also refuses `BLOCKED_DOMAINS` (and subdomains) for the page, every redirect, and the image; the connection itself uses a re-validated address (no DNS rebinding); IPv6 forms of private addresses are refused; once a reply has used up its searches or link reads, later tool rounds run with `tool_choice: none` and paused turns are not resumed (the declared tools never change within a reply, because thinking blocks are bound to them). Accepted demo risk: pictures found on the web are not content-moderated beyond the blocklist and the prompt rules (no SafeSearch or image classifier), and the app loads them directly from the third-party host, which therefore sees the viewer's IP address and user agent. |
